opsward.subagents#

Reuse a skill as a subagent: declare it in the skill, generate the twin, check the sync.

A Claude Code subagent is a Markdown file under .claude/agents/ whose frontmatter can preload a skill (skills: [name] injects the full SKILL.md body). So a skill that is also useful in its own context needs nothing but a thin twin that preloads it, restricts tools, picks a model and states the reply contract. The single source of truth stays in the skill: it opts in with spec-legal metadata keys (the Agent Skills spec allows string pairs there, and other hosts ignore them). Quote the values so a strict validator sees strings:

---
name: fleet-sweep
description: ...
metadata:
  subagent: "true"
  subagent-tools: "Bash, Read, Grep"
  subagent-model: "sonnet"
  subagent-reply-lines: "5"
  subagent-name: "fleet-sweeper"
---

Only subagent is required; the defaults are Read, Grep, Glob, Bash, no model (the host picks), 5 lines, and the skill’s own name. Three pure functions do the work, so generate and maintain share one source: subagent_spec() reads the declaration, render_subagent() renders the twin (with a marker line carrying a hash of what it was rendered from), and twin_status() classifies every skill/agent pair in a scan. Decision record: misc/docs/decisions/0009-skills-declare-their-subagent-twin.md.

opsward.subagents.render_subagent(spec, *, source)[source]#

Render the twin agent file for spec; source is the skill’s repo-relative path.

The body is deliberately short: the skill’s full content is preloaded by the host through the skills field, so the twin only adds the context contract.

>>> spec = SubagentSpec('sweep', 'sweep', 'Sweep and report.', 'Bash', 'haiku', 3)
>>> text = render_subagent(spec, source='.claude/skills/sweep/SKILL.md')
>>> text.splitlines()[1:4]
['name: sweep', 'description: Sweep and report.', 'tools: Bash']
>>> 'skills: [sweep]' in text and 'at most 3 lines' in text
True

str

opsward.subagents.twin_status(sr)[source]#

Classify every declared twin and every hand-written agent that preloads a skill.

  • invalid: the declaration cannot be rendered (see SubagentSpec.problems).

  • duplicate: two skills declare the same twin name; the first wins, the rest are reported.

  • missing: the skill declares a twin and no agent file exists.

  • stale: the agent file was generated from a declaration that has since changed.

  • in_sync: generated and current.

  • handwritten: an agent opsward did not generate, either carrying the name a skill declares for its twin (declared=True), or sharing a non-declaring skill’s name or preloading it via skills: (declared=False).

Return type:

Iterator[TwinStatus]
