opsward.evals#

Eval harness (opsward#17, gap 3): opt-in, report-only quality signals beyond the rubric.

Two layers, both of which report and never gate (model calls cost money and are nondeterministic, so the deterministic rubric stays the only gate):

  • LLM-as-judge for the rubric’s subjective dimensions (actionability, conciseness): judge_claude_md() asks a judge to score CLAUDE.md against an explicit rubric,

    samples times, and reports the median next to the rubric’s own score.

  • Golden tasks: run_golden_tasks() runs an agent on repo-specific tasks with and without a candidate config, and checks each output against the task’s expect / forbid patterns. The with-minus-without pass rate is the signal that a config helps.

The judge and the agent are injected. rubric_judge() (the default judge) and echo_agent() are free and deterministic – they exercise the harness and anchor the scale – while anthropic_judge() and anthropic_agent() make paid calls through the anthropic SDK (pip install 'opsward[eval]') and are never used by default.

>>> report = judge_claude_md("# P\n\n## Commands\n\n```bash\npytest\n```\n")
>>> sorted(report.scores), report.judge
(['actionability', 'conciseness'], 'rubric')
>>> tasks = [GoldenTask("kw", "Write f(a, b, c)", expect=[r"\*,"])]
>>> golden = run_golden_tasks(tasks, agent=echo_agent, config="Use `*,` before the 3rd arg.")
>>> golden.delta()
1.0

opsward.evals.parse_verdict(reply, *, max_score)[source]#

(score, reasoning) from a judge reply: the last JSON object in it with a score.

The last, because a judge that quotes a snippet or restates the format writes its verdict at the end. 9, 9.0 and "9" are all read as 9.

Raises:

ValueError – no JSON object with a score, or one that is not an integer in 0..max_score.

Return type:

tuple[int, str]

>>> parse_verdict('Quote {"a": 1}. Verdict: {"reasoning": "ok", "score": 12}', max_score=15)
(12, 'ok')

The free, deterministic judge: answers with opsward’s own rubric score.
