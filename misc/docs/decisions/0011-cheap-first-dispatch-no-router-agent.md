# 0011 — Cheap-first dispatch: routes, then the listing, then calibrated lexical retrieval; no router agent

## Status

Proposed (2026-10-19). Decides [thorwhalen/opsward#14](https://github.com/thorwhalen/opsward/issues/14); the wiring it describes is tracked in [thorwhalen/opsward#44](https://github.com/thorwhalen/opsward/issues/44). Accepting is the operator's act (ADR 0010 §2).

## Context

The issue asked for a few top-level entry agents that find and dispatch to the right specialist, built from `aw.PriorityRouter` with a retrieval-backed strategy and an escalation to an LLM on ambiguity, and for three decisions: the score-gap or abstention boundary and its calibration, how many entry agents, and when routing helps rather than hurts. `misc/docs/research/discovery_and_dispatch.md` had already warned that routing is not universally beneficial, and the #23 report (`skill_tiering_and_reachability.md` §5.2) had costed the always-on residue a router needs and deferred any router to usage evidence, the same gate priv#177 applies to its package-scout hook. What was missing was measurement, so this decision rests on `misc/docs/research/dispatch_probe.md`: fourteen trigger prompts through the host's own listing (13/14), an LLM run holding the complete 120-skill catalog (12/14 on the raw prompt in two draws; 11/14 and 9/14 on a one-line summary; ~15 s per decision), and `ir discover` over the skills corpus (lexical 12/14 top-1 at 0.05 s per call; hybrid with RRF fusion 11/14 at 11–13 s; summaries 0/14 lexical and 4/14 hybrid; abstention never fired because no `min_score` floor exists for the corpus). On n=14 no accuracy difference between the LLM arms is statistically distinguishable; the latencies and the collapse of retrieval on paraphrases are the robust results.

## Decision

1. **No new entry agent.** The entry surface stays what it is: the session the user talks to, its always-loaded routes (`CLAUDE.md`, briefs), the host's skill listing (T0 described, T1 name-only, per the #23 tiers), one discovery tool (`ir discover skills`) for everything not listed, and delegation through subagent twins (ADR 0009). There is no evidence that a router step improves on the listing, and it adds a separate ~15 s call with a 79k-character context per decision. The crowsnest lookout remains the one "top-level agent", and it dispatches to sessions, not to skills. Revisit when a measurement shows the listing missing where a router hits.
2. **The dispatch order is cheap-first, and a layer answers only when it is sure.** (a) A route: a `CLAUDE.md` line or a brief that names the skill next to its condition, deterministic and free. (b) The listing: description matching in the main context, no extra hop. (c) Lexical retrieval: `ir discover skills --mode lexical` over the raw prompt, one record per skill name, wrapped in `aw.routing.ConfidentRetrievalStrategy` with a calibrated floor and a relative gap. (d) Escalation: an LLM adjudication over the top-k candidates from (c) and the raw prompt, never over the whole catalog, only when (c) abstains. Layers (a) and (b) are the host reading prose; (c) and (d) are code. **Neither (c) nor (d) exists as a working chain yet**: `aw` has the generic strategy ([thorwhalen/aw#5](https://github.com/thorwhalen/aw/pull/5)) but with an absolute gap and defaults that answer any ranking ([thorwhalen/aw#7](https://github.com/thorwhalen/aw/issues/7)); the `ir` adapter, the de-duplication and the adjudicator are #44. Until #44 lands, nothing routes automatically beyond (a) and (b), which is the measured 13/14 path.
3. **Whatever routes must see the user's words.** A paraphrase is a lossy channel: retrieval collapses on it (0/14 lexical, 4/14 hybrid) and the LLM arm lost one to three cases on it across two draws. Nothing in the chain may summarise the request before matching it.
4. **The abstention boundary is defined, not yet calibrated.** Floor: the lexical score floor `ir calibrate-min-score` produces for the `skills` corpus, persisted with the corpus (none exists today, which is why no `ir` arm ever abstained). Gap: the runner-up at or below 0.9 of the top score (`ir`'s `rel_threshold`; `aw`'s strategy needs the relative form, aw#7), applied after collapsing copies of one skill to one record (the live corpus holds 943 records for ~525 skills and copies tie at identical scores). Prerequisites filed as [i2mint/ir#111](https://github.com/i2mint/ir/issues/111). Until both exist, layer (c) is not enabled.
5. **When routing helps and when it hurts.** It can only help for a skill that is not in the session's listing (T2/T3) or whose description the budget dropped; that case was not in the probe (all fourteen targets were listed T0 skills) and is the expected use, not a measured result. It hurts whenever the skill is already listed with its description, because the listing is as accurate and needs no extra call, and whenever the request reaches the router as a summary. The repeat error in every arm is a naming collision (`tw-deploy`/`twp-deploy`, `zodal-ecosystem`/`zodal-collection(s|-ui)`), which no router fixes and a naming lint does, with the caveat that the `twp-deploy` gold label is itself arguable.
6. **Where the code lives.** The generic strategy is in `aw` (search engine injected, no new dependency). The retrieval engine and its calibration are `ir`'s. The adapter and the adjudicator are #44. opsward owns the decision, the measurement and the diagnosis of what makes dispatch fail (naming collisions, shadowing, listing budget: #35).

Rejected: a router subagent as the entry point (no measured gain, a certain extra call); hybrid retrieval with RRF fusion in the hot path, as `ir` implements it today (11–13 s per call for a lower score, and scores unusable for a gap test; `--fusion blend` untested); a catalog MCP server as the first surface (a tool must be called, the same failure mode as a skill, while the listing has no decision point); summarising the request before routing.

## Consequences

- Nothing new runs by default, and nothing new can mis-route: the measured path is the one every session already has, and the retrieval layer stays off until it has a calibrated boundary and a de-duplicated corpus.
- The three decisions the issue listed: entry agents, zero new; boundary, a calibrated lexical floor plus a 0.9 relative gap after de-duplication (defined, blocked on ir#111 and aw#7); helps-vs-hurts, as in §5, with the helping case explicitly unmeasured.
- Re-run the probe (`routing_probe.py`, ~70 Sonnet calls) with a fourth arm once #44 assembles the chain, after the corpus is de-duplicated, or when a CLI version changes the listing budget; the no-router decision stands while the listing scores at least as well as a router on that set.
- priv#177 inherits this evidence: its package-scout and prompt-router hook remain gated, and the gate now has a baseline to beat.
