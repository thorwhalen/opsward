# Decision log

One line per small or medium decision, newest last, as a Y-statement: *In the context of …, facing …, we decided for …, to achieve …, accepting …, because …*. A decision that is expensive to reverse, crosses a package boundary, or touches a published API gets a numbered ADR in this folder instead (`opsward decision new "title"`). Append with `opsward decision note "…" --write`.

- 2026-10-19 — In the context of the CLI goldens (#35), facing a `diagnose` that now reads the user's global skill scope, we decided to record and replay with `CLAUDE_CONFIG_DIR` pinned to an empty directory, to keep the goldens portable, accepting that a shadowing or budget note never appears in a golden, because a machine-dependent golden fails on every other machine.
- 2026-10-19 — In the context of the 3.10 golden, facing a local uv-built CPython 3.10.13 whose argparse words the invalid-choice and required-arguments messages the 3.12 way, we decided to keep the committed wording for those two cases and re-record only the cases a change moves, accepting a hand-merged golden, because CI's 3.10 is the arbiter of that file.
- 2026-10-19 — In the context of subagent twins (#26), facing two skills that could declare the same twin name, we decided that the first in scan order wins and the rest are reported as `duplicate`, accepting that the winner is alphabetical rather than chosen, because a deterministic rule the check can state beats a silent overwrite.
- 2026-10-19 — In the context of the canonical-location search (#35), facing `tests/data/skills` being mistaken for a package's skill home, we decided to recognise only `skills/` and `<pkg>/data/skills/` where `<pkg>` has an `__init__.py` at the root or under `src/`, accepting that a namespace or JS package is not detected, because skill-package-setup names exactly those two locations.
- 2026-10-19 — In the context of the always-on skill set (#23), facing a budget that 39 usage-selected skills overflowed, we decided to exclude skills the global CLAUDE.md already routes by name from the described tier, to keep the listing under the cap, accepting that a route-named skill is never description-triggered, because a route reaches it by path or name anyway.
- 2026-10-19 — In the context of the decision commands (#16), facing a choice between `decision-new`/`decision-note` as flat commands and a nested `decision` group, we decided for the nested group under the one `opsward` parser, to keep the pinned surface a single golden, accepting that a bare `opsward decision` prints the top-level usage and exits 0 (cw's grouping behaviour), because the issue named `decision new` and the goldens pin whatever the grammar does.
- 2026-10-19 — In the context of the dispatch probe (#14), facing a first run whose router arms read a stderr warning as the model's answer, we decided to re-run only those arms with stdout-only parsing and keep the listing arm's results, to save 14 Sonnet calls, accepting that the arms were not run at the same moment, because the listing arm's transcripts were already scored from `Skill` tool calls and unaffected by the bug.
- 2026-10-20 — In the context of ADR 0011 (#44), facing a 0.9 relative gap chosen before measurement, we decided on 0.75 (9 confident-right, 5 escalated, 0 confident-wrong on the probe set, against 12 right and 2 confident-wrong at 0.9), recording it as provisional because the probe scripts live only on the Mac; the re-sweep is filed as an issue.
